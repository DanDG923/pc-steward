## Desktop execution and real-update evidence

On 2026-07-28 the product owner approved a Firefox `152.0.6` → current-version exercise. Firefox `152.0.6` was installed and correctly appeared as a WinGet-updatable package with `153.0.1` available. The first attempt exposed a missing desktop execution action. Subsequent attempts exposed a missing helper runtime DLL beside the desktop output, then an outer-review-dialog lifecycle crash after the UAC path returned. Both faults were diagnosed from the observed behavior and Windows error reporting, then remediated in the pending change set.

The desktop now exposes a separate review action only for a verified update. It obtains a fresh live source match from persisted source-disclosure consent, constructs the typed selection from installed/source evidence only, displays immutable fields for a separate confirmation, rechecks the exact evidence before saving/running, and performs controlled post-update inventory before any Success result. A source change, stale/unavailable source, unsupported scope/architecture, or failed verification prevents success. `ReviewedUpdateExecutionWorkflowTests` and `InventoryWorkflowUpdateSourceTests` cover selection consent/exactness, review-to-execution substitution rejection, immutable job persistence and verification-only success.

The final accepted UAC attempt took longer and updated Firefox. Direct exact WinGet re-inventory returned only `Mozilla Firefox (x64 en-US)  Mozilla.Firefox  153.0.1`, proving the expected installed version; no Available column remained. This establishes the package/version outcome, but not that the desktop successfully rendered its own post-update outcome before the lifecycle remediation. Firefox was uninstalled immediately after recording the result, and the one-time current-user code-signing certificate was removed from both `My` and `Root` stores.

## WinGet community repository posture

The community repository is treated as a strong trust signal, not blanket execution authority. PC Steward uses the exact approved WinGet package ID and source, owns the fixed executable/arguments, never bypasses installer hash validation, and requires explicit review/confirmation. The Firefox evidence did not add silent updates or generalize trust to arbitrary package matches. Publisher or signer changes remain a review/hardening concern; this evidence does not claim that such changes are surfaced automatically.
