## 3. Session order and global stop rules

Order: **A → B → C.** A runs first because it touches no PC Steward file. If Chocolatey does not match 2.7.5, redeploying cannot lead to activation. Part A may also be run on its own before B and C exist, under the same approval wording.

- "Stop" means: run no further step in any part, do not retry, and report only the console token. A stopped part is never re-run without a new exact approval.
- Do not proceed from A to B unless O5 is `PASS-READABLE`, `matchesPinnedRelease` is `true`, and (if H3 ran) AQ1UAC is not `FAIL`.
- Do not proceed from B-prep to B-exec unless every B-prep block printed its OK token (`PREFLIGHT-OK`, `B0-OK`, `B1-OK`, `B2-OK`, `B3A-OK`, CheckOnly `"result": "Pass"`, `B3C-OK`), the cross-checks in §5 hold, and approval 1b has been filled from that output and given by the owner.
- Do not proceed from B to C unless B ends with native exit 0, protected phase `validated`, the independent validator reports `pinned-unsigned-v2` with `helperProtocol` 2, and the database hash is unchanged.
- An unexpected UAC or certificate prompt (wrong program, wrong publisher, or a second prompt) gets **No**, followed by stop.
- No result in this session is admission, success or a gate closure by itself. Results feed an independent review, and then the owner decides.

### 5.1 How the blocks run

- Each block runs **once**, in its own fresh 64-bit Windows PowerShell 5.1 process (`C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe -NoLogo -NoProfile -NonInteractive -Command -`, fed the lines unchanged), as the owner's normal non-elevated user. Every line is a complete statement; do not re-wrap. Only B0.1 may be repeated, and only after the owner has corrected a precondition it reported.
- Line **V** (below) starts every block. It names the work folder and nothing else.
- `<CHECKOUT>` (B0.1 and B0.2) is the absolute path of the owner's clone, with every `'` in it doubled (`''`) because it sits inside a single-quoted string. It is the only substitution in B-prep and is never pasted back.
- Every child process a block starts gets `$null |` as its standard input, so it cannot read the block's remaining lines from the heredoc.
- A line beginning `STOP:`, a non-zero `…-EXIT` value, or a PowerShell error ends the stage: run no later block, retry nothing, delete nothing, and report the token. B1-X may run once after a B1 stop to extract a sanitized error line. Git's own progress or warning text (captured in B0.1 and B0.2, where only its line count is printed) is never treated as an error and is never reported verbatim.
- The caller is always run **from captured, hash-checked bytes** (its header rule): the block reads the file once, hashes those bytes, and runs exactly those bytes through `[ScriptBlock]::Create`. The copy script, builder and validator run with `-File` after an immediate hash check (they need `$PSScriptRoot`). Same-user changes between the hash and the read are inside the accepted owner-account trust assumption (§12).
- `-ExecutionPolicy Bypass` is process-scoped (Part A and Task 48 precedent); the caller still refuses an enforced MachinePolicy/UserPolicy.
