### Secured gate prerequisite — interface and scope

`Storage/CurrentUserOperationGate.cs` produces `OperationGateOwnership` through `Open()` and synchronous, bounded `TryAcquire(TimeSpan, CancellationToken)`. Following the least-privilege Opus proposal, only that user is granted access; neither Administrators nor SYSTEM requires access because the elevated helper never owns this gate. Creation uses `CreateMutexExW` with explicit owner/protected DACL; every open and acquisition queries owner+DACL from the handle with `GetSecurityInfo`, and accepts only the exact user-only policy. Native libraries resolve from System32. The handle is noninheritable and requests only synchronization, mutex modification and security-read rights.
