## Scope and interfaces

No product runtime, provider, database or installed state change. Keep v6 removal compatibility and existing transaction-owned cleanup. Existing candidate is immutable evidence; tests use unique isolated synthetic directories.

- Create `scripts/OwnerOnlyPayloadIntegrity.ps1`. Installer/validator dot-source it. It compiles a narrowly scoped `PCSteward.Deployment.PayloadIntegrity` helper with no execution/signing/deletion API. Public methods: `ReadPinnedFile(path, sha256) -> byte[]`, `AssertTree(root, PayloadFile[])`, `CopyTree(source, destination, PayloadFile[])`, `GetUnsignedImage(path) -> ImageIdentity`, `AssertSignedImage(path, ImageIdentity)`, `AssertSignerBlob(path, thumbprint)`. Models contain relative path/length/SHA-256 and original image length/raw SHA-256/checksum. PowerShell wrappers: `Read-OwnerOnlyCandidateManifest(Path, ExpectedSha256)`, `Test-OwnerOnlySignedExecutable(Path, Identity, ExpectedThumbprint)` and `Assert-OwnerOnlyPayloadProvenance(InstallRoot, StateRoot, State)`.
- Manifest limits: 1 MiB JSON, 512 entries, 256 MiB aggregate/file ceiling; unsigned PE apphosts at most 16 MiB. Reject noncanonical Windows names, aliases/collisions, ADS, traversal, reparse escapes and extra files/directories. Stable read handles deny concurrent write/delete; resolved file paths must equal their approved canonical paths.
- Image identity: a strict full-byte PE32+ x64 equivalence check, not a claim of SIP digest equivalence. Unsigned images must have no certificate or overlay, with FileAlignment-aligned sections/length. Reconstruct the unsigned prefix by restoring its recorded checksum and zero certificate-directory fields, then require its raw SHA-256 from the pinned manifest. Require certificate offset exactly at original EOF, one bounded certificate record/strict DER CMS and no extra overlay. Existing Windows Authenticode verification separately proves file binding/trust/signer under the same held file. All original resources/debug/import/section/header bytes are included. Unsupported layouts block rather than broaden the profile.
- Installer parameters add mandatory `CandidateRoot`, `CandidateManifestPath`, `CandidateManifestSha256`. New completed ledger remains v6 for remover compatibility, with `payloadOrigin=pinned-unsigned-v1`, approved manifest hash, protected `candidate-manifest.json`, and two executable image identities. Legacy completed v6 ledgers without new-route fields keep legacy validator behavior; partial/inconsistent new-route fields fail. No schema version silently gains guarantees.
- Create synthetic PowerShell fixture script under `tests/PCSteward.Security.FixtureTests/Fixtures/` and a normal MSTest invoking it under Windows PowerShell. Test actual shared helper behavior, not a second implementation. Add a narrow existing caller/exit-code harness helper only if needed; exercise success/nonzero child processes without touching installed roots.
- Create `scripts/Wait-OwnerOnlyDeploymentProcess.ps1`: `Wait-OwnerOnlyDeploymentProcess(Process, TimeoutMilliseconds) -> UInt32` retains the caller's native process handle before waiting, reads the kernel exit code, and throws on timeout/query failure. It does not start/kill a process or infer success from null. Consumed by the later exact deployment caller and exercised with synthetic child exits 0/7.
- Dialogue refinements: `ImageIdentity(bytes, sha256, originalChecksum)` reconstructs the exact unsigned bytes and compares the raw manifest hash, with FileAlignment and certificate offset exact. CMS is strict SHA-256/RSA/one signer/one certificate/no CRL/unsigned attributes; Windows Valid+Authenticode remains required under a held file. Sign/check in protected staging before installing. `CopyTreeProtected` creates descendant directories/files with the exact admin-owned ACL atomically; `WriteProtectedFile` does the same for manifest/ledger writes. Normal `CopyTree` remains for isolated non-elevated fixtures/materialization. This avoids a temporary default-owner write window before the final ACL verification. No caller-provided production root switch is introduced.

## Ordered work and gates

### Fresh review follow-up interfaces (M1/L1–L5)

M1 is a readiness condition regardless of its conditional severity: remove the reviewed mutable-script/compiler substitution paths, while explicitly retaining the trusted owner-account/session assumption. Active same-user control of CLR startup, caller, signer-key use or CurrentUser trust stores is not isolated by this test route and must be disclosed at action-time approval. Existing TM-04/TM-06 helper evidence excludes clean installer lifecycle. Create `scripts/OwnerOnlyExecution.ps1` with pure PowerShell/.NET ACL/root checks (no Add-Type). It produces admin-owned code and compiler security descriptors; the compiler directory inherits only SYSTEM/Administrators FullControl plus OWNER RIGHTS ReadPermissions, preventing a file owner from obtaining implicit WriteDac. `Assert-OwnerOnlyExecutionEnvironment(ScriptRoot)` requires the reviewed fixed ProgramFiles execution-root shape and matching protected compiler TEMP/TMP before elevated Add-Type. Installer/validator/shared helper/exit helper consume it.

Create `scripts/Invoke-OwnerOnlyApprovedRedeployment.ps1` as an inert bootstrap template requiring an embedded exact authority record. The later caller supplies its reviewed contents as immutable encoded-command data (verified against a literal hash before elevation), not `-File` from a mutable checkout. It creates a unique reviewed ProgramFiles execution root with ACLs at creation, copies the six exact pinned scripts into it using stable reads and raw hashes, verifies the protected copy, sets private compiler TEMP/TMP, then invokes only that copy. The record binds installing SID, original ledger/signer, candidate root/manifest, all script hashes and fixed install/state roots. No host action is performed during template preparation. Compiler TEMP is restored in finally; unknown/partial results do not trigger a retry. The exact plan must disclose retained execution infrastructure and separate cleanup authority.

L3 removes staging before committing the completed ledger.
